* Build Guide

[[file:./readme.org][Back to Documentation]] | [[file:../zh-CN/构建指南.org][中文版]]

** Recommended Build

zpp is built as an independent ZetaX project. It keeps zpp-specific build logic
in =builder/=, while shared dependency versions and package configs come from
=zeta_forge deps=.

From the zpp checkout:

#+begin_src sh
cd "$ZETAX_ROOT/zeta_forge"
./zbuild.py install deps --profile debug

cd "$ZETAX_ROOT/zpp"
./zbuild.py rebuild --profile debug
#+end_src

=ZETAX_ROOT= is the top-level ZetaX workspace root. In the standard layout,
=zpp= and =zeta_forge= are sibling checkouts under it.

zpp does not run Conan. If =spdlog=, =fmt=, =RapidJSON=, or =GTest= package
configs are missing, install the shared environment with
=zeta_forge/zbuild.py install deps= first.

** Delivery Selection

The default is the core library =zpp= only. Select =zpp_nng=, =zpp_folly=,
=zpp_hpx= and examples by native target name. Selection derives CMake options;
tests and examples are not implicitly included in build.
#+begin_src sh
./zbuild.py build zpp_nng zpp_hpx
./zbuild.py test zpp_nng --profile debug
./zbuild.py dev zpp_core --profile debug
./zbuild.py install zpp
#+end_src
=run= only launches existing outputs. =dev= builds and runs once. See
[[file:../../BUILD.org][BUILD.org]] for defaults, installation scope and cleanup impact.

** NNG 2.0 RC Migration

The Forge NNG source is pinned to =v2.0.0-rc.1= at
=8fde97db953012882298254bc4753d53e9155bb6=. Install the updated NNG before
building or testing =zpp_nng=. See the
[[file:../../../zeta_forge/doc/nng_upgrade_cn.org][workspace upgrade sequence]].

=dialer::set_addr= is replaced by
=int bind(const nng_sockaddr &local_address) noexcept=, matching upstream
=nng_dialer_bind=. Call =create -> bind -> start= with a zero source port.
The address is borrowed only during the call. Errors retain NNG error codes,
including =NNG_ENOTSUP= for transports without binding support.
Existing explicit receive limits and message ownership remain unchanged.

On Windows, NNG 2 uses AF_UNIX for =ipc://= (equivalent to =unix://=).
Use =winpipe://= to retain named-pipe interoperability with older applications.
Linux IPC paths keep their existing meaning. Windows behavior is not covered
by the Linux Release verification procedure.

#+begin_src sh
./zbuild.py build zpp_nng --profile release
./zbuild.py test zpp_nng --profile release
./zbuild.py install zpp_nng --profile release
#+end_src

** Direct CMake Usage

Direct CMake usage is for advanced/manual scenarios only. It must pass explicit
dependency paths because zpp no longer performs fallback auto-discovery for
=ZETA_CMAKE_UTIL_DIR= or =ZETA_DEPS_CMAKE_DIR= inside CMake.

#+begin_src sh
cmake -S . -B build/Debug \
  -DCMAKE_BUILD_TYPE=Debug \
  -DZETA_CMAKE_UTIL_DIR="$ZETAX_ROOT/zeta_forge/cmake_util" \
  -DZETA_DEPS_CMAKE_DIR="$ZETAX_ROOT/zeta_forge/install/lib/cmake/zeta_deps/Debug"

cmake --build build/Debug
#+end_src

The old =cbuild= helper is no longer the recommended entry for zpp because it
may miss the installed zeta_forge dependency package environment.

Direct CMake users enabling =ZPP_BUILD_HPX_MODULE= must also pass
=ZPP_HPX_EXPECTED_GIT_COMMIT= with the exact commit from
=zeta_forge/3rd/hpx= and set =ZPP_HPX_DEPENDENCY_CMAKE_DIR= to
=zeta_forge/builder/hpx/cmake/conan_compat/packages=. The project builder
supplies both automatically.
