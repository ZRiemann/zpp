** 当前入口

默认只构建核心库 zpp；扩展库和示例按真实目标名显式选择。
测试自动配置并构建所选原生工程的正确性测试集合。
#+begin_src sh
./zbuild.py build zpp_nng zpp_hpx
./zbuild.py test zpp_nng --profile debug
./zbuild.py dev zpp_core --profile debug
./zbuild.py install zpp
#+end_src
完整语义见 [[file:../../BUILD.org][BUILD.org]]。

** NNG 依赖和接口

依赖基线为 Forge 安装的 NNG =2.2.0-dev=。构建配置和已安装包的依赖查找
检查 NNG 2.x 头文件，并链接验证 =nng_dialer_bind= 和
=nng_pipe_get_scheme=。开发版不是 2.2 正式版，此基线不承诺支持旧版。
构建 =zpp_nng= 前通过 Forge 安装 NNG。

=pub_sub_device::start= 提交异步转发操作，完成错误由回调报告；停止时先取消
并等待，再清理资源。=pipe::get_scheme= 返回 NNG 借用字符串，pipe 存续期间有效。
socket 协议统计是累计协议事件，与 pipe 传输计数口径不同，也不代表对端应用
已接收；协议未提供的计数在摘要中为空。

=dialer::set_addr= 替换为
=int bind(const nng_sockaddr &local_address) noexcept=，对应上游
=nng_dialer_bind=。调用顺序为 =create -> bind -> start=，源 port 必须为零。
地址仅在调用期间借用，保留 NNG 错误码；不支持绑定的 transport 返回
=NNG_ENOTSUP=。现有显式接收上限和消息所有权语义保持不变。

Windows 的 =ipc://= 改为 AF_UNIX，与 =unix://= 等价；需要与旧应用通过
named pipe 互联时使用 =winpipe://=。Linux IPC 路径保持原有含义。
Windows 行为不包含在当前 Linux Release 验证流程中。

#+begin_src sh
./zbuild.py build zpp_nng --profile release
./zbuild.py test zpp_nng --profile release
./zbuild.py install zpp_nng --profile release
#+end_src

** 直接使用 CMake

直接使用 CMake 只建议用于高级或手动场景。zpp 的 CMake 配置阶段不再对
=ZETA_CMAKE_UTIL_DIR= 与 =ZETA_DEPS_CMAKE_DIR= 做 fallback 自动推导，必须显式传入
依赖路径。

#+begin_src sh
cmake -S . -B build/Debug \
  -DCMAKE_BUILD_TYPE=Debug \
  -DZETA_CMAKE_UTIL_DIR="$ZETAX_ROOT/zeta_forge/cmake_util" \
  -DZETA_DEPS_CMAKE_DIR="$ZETAX_ROOT/zeta_forge/install/lib/cmake/zeta_deps/Debug"

cmake --build build/Debug
#+end_src

旧的 =cbuild= helper 不再作为 zpp 推荐入口。它会执行独立 CMake 配置，可能拿不到
zeta_forge 安装的共享依赖 package config。

直接使用 CMake 并启用 =ZPP_BUILD_HPX_MODULE= 时，还必须通过
=ZPP_HPX_EXPECTED_GIT_COMMIT= 传入 =zeta_forge/3rd/hpx= 的精确 commit，并将
=ZPP_HPX_DEPENDENCY_CMAKE_DIR= 指向
=zeta_forge/builder/hpx/cmake/conan_compat/packages=；项目 builder 会自动注入两者。
